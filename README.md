# Mention — диффузионная языковая модель, обучаемая бесплатно из «научного интереса»

Этот репозиторий — самодостаточный пайплайн обучения **маскированной
диффузионной языковой модели** (dLLM, рецепт LLaDA) на бесплатных GPU:

- **Kaggle** — до 2 GPU (T4/P100) на сессию, ~30 GPU-часов в неделю на аккаунт;
- **Google Colab Free** — 1×T4, дополнительные часы;
- **2+ аккаунта Kaggle** — можно подключить несколько смен (см. дисклеймер ниже);
- локально — только для отладки (1660 Ti / CPU).

Все смены обучают **одну модель**: общие чекпоинты лежат в приватном
репозитории Hugging Face, а «аренда» (lease) гарантирует, что одновременно
учит только одна смена.

---

## Как это работает

```
 Kaggle acc #1 ─┐                    ┌─ Kaggle acc #2
 Kaggle acc #2 ─┼── HF Hub (repo) ──┼─ Colab Free
 Colab Free ────┘  checkpoints +     └─ (локальная отладка)
                    lease (аренда)
```

1. Смена стартует: скачивает **последний чекпоинт** (`model.safetensors`,
   `meta.json`, токенизатор), проверяет **lease**.
2. Если lease свободен — занимает его и учит модель.
3. Каждые **2 часа** и в конце бюджета — сохраняет чекпоинт и заливает в hub.
4. Сессия Kaggle живёт ~12 часов: скрипт сам завершается за 10 минут до
   лимита (`--budget-min 660`), всё сохранив. Следующая смена продолжит с того
   же шага.
5. lease «сердцебиение» обновляется каждые 45 минут; если смена умерла
   внезапно, через 90 минут lease протухает и другие смены могут продолжить.

**Лимиты, которые мы честно принимаем:** оптимизаторные моменты (Adam m/v)
не сохраняются — после каждого резюма оптимизатор стартует заново. Для
претреина это почти незаметно; зато чекпоинт компактный (~0.6 ГБ для 300M).

## Быстрый старт

### 0. Локальная установка (только для отладки)
```bash
python -m venv .venv
.venv/Scripts/activate          # Windows (Git Bash: source .venv/Scripts/activate)
pip install -r requirements-dev.txt
```

### 1. Токенизатор
```bash
python scripts/train_tokenizer.py --vocab-size 49152 --out artifacts/tokenizer
```
Скачает сэмпл (~200k текстов из FineWeb-Edu и столько же из mC4-ru),
обучит BPE и сохранит `artifacts/tokenizer/tokenizer.json`.

### 2. Создать приватный HF-репозиторий и залить токенизатор
```bash
export HF_TOKEN=hf_...            # любой токен
python scripts/seed_hf_repo.py \
    --repo YOUR_HF_USERNAME/mention-ckpt \
    --artifacts artifacts/tokenizer \
    --config configs/pretrain_300m.yaml
```

### 3. Локальный смоук-тест (офлайн, без GPU и интернета)
```bash
python scripts/run_lane.py \
    --config configs/pilot_40m.yaml \
    --lane smoke \
    --local-dir runs/hub_smoke \
    --smoke --steps 20
```
Должен пройти 20 шагов на CPU и сохранить чекпоинт в `runs/hub_smoke`.

### 4. Запуск на Kaggle (для каждой смены — свой аккаунт)
1. Залей код на GitHub (`git push`), либо загрузи папку в датасет Kaggle.
2. Создай новый Notebook из `notebooks/kaggle_lane.ipynb` (загрузи файл).
3. Включи **Internet** (Settings → Internet → ON).
4. `Add-ons → Secrets`: добавь `HF_TOKEN` (уникальный для каждого аккаунта).
5. В ячейке «git clone» замени `YOUR_USERNAME` на свой GitHub-ник.
6. В последней ячейке замени:
   - `--lane kaggle-1` → `kaggle-2` для второго аккаунта (и так далее);
   - `--repo YOUR_HF_USERNAME/mention-ckpt` → свой репозиторий;
   - при желании `--config configs/pilot_40m.yaml` → `pretrain_300m.yaml`.
7. `Runtime → Run all`. Для запуска следующей смены — просто нажми Run all
   снова: она продолжит с последнего чекпоинта.

### 5. Запуск на Colab Free
Те же шаги с `notebooks/colab_lane.ipynb`:
- секрет `HF_TOKEN` через кнопку «ключ» слева;
- `--lane colab`, `--repo ...`.

## Сколько это займёт

| Этап | Токены | Оценка времени |
|---|---|---|
| Пилот ~50M (`pilot_40m.yaml`) | ~0.8B на смену | **~1 неделя** при 1–2 сменах в день |
| Основной ~300M (`pretrain_300m.yaml`) | ~6.5B на смену | **~1.5–2 месяца** (2 Kaggle + Colab) |

Точность: на 2×T4 модель 300M выдаёт примерно 6–8k токенов/с. Помните:
каждый GPU читает свой поток данных, так что реальный объём «увиденных»
токенов за шаг = `micro_batch × grad_accum × seq_len × число GPU`.

## Как следить за обучением

- `runs/<lane>/loss.csv` — история `step, tokens, loss, tokens/s, lr`.
- `runs/<lane>/checkpoint/meta.json` — последний сохранённый шаг.
- В hub: `huggingface.co/<user>/mention-ckpt` — файлы `checkpoint/...`,
  `lease/lease.json` (owner, heartbeat_at).

Полезные команды:
```bash
# показать последний шаг в hub
python -c "from mention.sync import CheckpointHub; h=CheckpointHub(backend='hf', repo_id='USER/mention-ckpt', token=os.environ['HF_TOKEN']); print(h._read_json('checkpoint/meta.json'))"
```

## Разбор полётов (проблемы)

| Симптом | Причина / решение |
|---|---|
| `lease busy` в логе | Другая смена сейчас учит (или умерла меньше 90 мин назад). Просто подожди и перезапусти сессию. Если прошлая сессия точно мертва (например, после таймаута) — добавь флаг `--force` в команду запуска: он отберёт lease сразу. |
| NaN в loss | Слишком большой LR / FP16-переполнение. Уменьши `learning_rate` в 2–4 раза, или выключи `fp16: false` (медленнее, но стабильнее). |
| Очень медленно | Проверь, что в сессии T4 (не P100); что `--mixed_precision=fp16`; что нет загрузки CPU на 100% (чипы). |
| Чекпоинт не появляется в hub | Проверь `HF_TOKEN` (права на запись), интернет в сессии, `--repo` совпадает. |
| Сессия Kaggle «зависла» | Обычное дело: скрипт сам спасёт состояние по бюджету; если нет — lease протухнет через 90 мин, и следующая смена продолжит. |
| Токенизатор не найден на старте | Сначала выполни `scripts/seed_hf_repo.py` (шаг 2) — токенизатор подтянется из hub. |

## Дальше (пост-обучение)

Когда претрейн даст связный текст:
- **SFT**: обучи модель на инструкциях (можно прямо на Kaggle той же сменой,
  взяв за основу тот же `run_lane.py`, но с другим датасетом).
- **DPO/GRPO**: для выравнивания — этап после SFT.
- **Инференс**: `mention/generate.py` — параллельное размаскирование
  (4–8 шагов вместо 2048 авторегрессионных).

## Лицензия и этика

Проект создан «ради науки» (C исследовательскими целями). Модель не должна
использоваться в коммерческих сервисах без отдельной оценки. Данные — только
открытые корпуса (FineWeb-Edu, mC4). Все ключи хранятся локально/в секретах
блокнотов и не попадают в репозиторий.
